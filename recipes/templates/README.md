# 🎯 정답 대조 템플릿 — ⛔ 이것이 «왜» 필요한가

## 0. 한 줄

> ***확률이 붙어 온다고 그 확률이 «맞는» 것은 아니다.*** 「보정됐다(calibrated)」는
> ***「0.9 라고 말한 것들 중 실제로 90%가 맞는다」***는 뜻이고, 그것은 ***정답이 있어야만*** 잴 수 있다.

## 1. 정답이 «없으면» 무엇을 못 하나

```
⛔ 임계를 정할 수 없다      0.9 로 자를지 0.7 로 자를지 «감»으로 긋게 된다
                           (지금 기본값 0.9/0.7 은 ***커뮤니티 값***이지 우리 데이터의 값이 아니다)
⛔ 자동/사람 경계를 못 판다   "85%는 자동, 15%는 사람" 을 «근거 없이» 말하게 된다
⛔ 나아졌는지 못 잰다        프롬프트를 고쳐도 좋아졌는지 알 수 없다
```

> 🩸 Jev 창시자가 지적한 패턴이 정확히 이것이다 —
> *"기업들이 배운 교훈은 사업상 손실이 걸린 결정을 AI 에 맡기지 말라는 것. **모든 비용이 회사가 아니라
>   «사용자»에게 돌아가게** 하라는 거죠. **끔찍한 패턴이지만 지금 AI 의 현실입니다.**"*
> ⇒ ***정확도를 모르는 채 사람을 빼면 그 비용이 «고객»에게 간다.***

## 2. 그래서 이 템플릿이 하는 일

```
입력 칸   id · 업무 · 부서 · 비고(⛔ «건수» 필수) · 현재판단
정답 칸   정답_자동화가능 (true/false) · 정답_이유 · 정답_채운사람     ← ⭐ «사람»이 채운다
```
⛔ **밑줄(`_`)로 시작하는 칸과 `정답_*` 칸은 모델에게 «안 간다».** 설명·정답을 같은 파일에 둬도 안전하다.

## 3. 쓰는 순서

```
① 이 템플릿을 복사해 실제 업무 ***50~100건***을 채운다
   ⛔ 인터뷰로 만들지 말고 «이미 있는 문서»(업무분장표·SOP·ERP 메뉴)에서 뽑는다
② 「현재판단」을 사람이 채운다   ← ⛔ 모델에게 물으면 표현에 따라 «정반대»로 뒤집힌다(실측)
③ elanous ax-screen <파일>       (수 분 · $0.005 미만)
④ ⭐ 1·2순위 «전부»를 그 업무를 아는 사람이 보고 `정답_자동화가능` 을 채운다
⑤ 맞은 수를 «센다»             ← ***이것이 산출물이다. 표가 아니다.***
```

## 4. ⚠️ ⑤에서 «세는 법» — ⛔ 한 수로 접지 마라

```
전체 정확도          맞은 수 / 전체            ⇒ ⚠️ 가장 덜 쓸모 있다
1순위의 정밀도       1순위 중 정답이 true 인 비율  ⇒ ⭐ ***헛걸음 비용***을 말한다
제외의 재현율        제외 중 정답이 true 였던 것   ⇒ ⭐⭐ ***놓친 기회***를 말한다 — 가장 비싸다
```
🔑 **④에서 1·2순위만 보면 「제외의 재현율」을 못 잰다.** ⇒ 📌 ***제외 중에서도 «무작위 10건»을 같이 본다.***
⛔ 안 그러면 *"고른 것은 맞았다"* 만 알고 *"놓친 것"* 은 영영 모른다.

## 5. ⛔ 이 템플릿이 «답하지 못하는» 것

- **몇 건이면 충분한지** 모른다. 50~100 은 ***실무 감각이지 통계적 근거가 아니다.***
- **사람의 정답도 틀릴 수 있다.** 두 사람이 갈리면 그 업무는 «애매한 것이 맞다»로 적어라.
- **이 파일 형식은 `ax-screen` 전용**이다. 다른 레시피는 자기 정답 칸이 따로 필요하다.
