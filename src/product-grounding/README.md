# 🧾 상품 접지 — «체크리스트»가 판정한다

> 대표 2026-09-10: *"앞으로 여러 사이트가 생길수 있어서 건별이 아니라 체크리스트 확인이 되야겠네요"*

## 왜 「사이트별 어댑터」가 아닌가

어댑터를 늘리면 **새 사이트마다 코드를 짓는** 일이 된다. 그러면 ①무엇이 빠졌는지 말해 주는 자가 없고
②어댑터가 늙어도 «조용히» 늙는다.

⇒ 대신 ***「무엇을 얻어야 하나」를 한 곳에 두고 페이지가 그것을 냈는지 «잰다»***.
**새 사이트 추가 = 「체크리스트가 이름을 댄 빈 칸」을 메우는 일**이 된다.

## 🩸 이 설계가 생긴 «내 오류» 넷

1. **키만 뒤지고 「없다」고 읽었다 — 두 번.** 쿠팡의 `기능성`·`제조국` 은 «다른 칸의 값 안»에 있었다.
   ⇒ ***판매 사이트는 고시 여러 칸을 한 칸에 이어 붙인다.*** `findSpec` 이 키·값을 «둘 다» 본다.
2. **본문 grep 은 «광고»를 문다.** `기능성` 9건 중 대부분이 `ui-recommendation-list` 의 «다른 상품».
   ⇒ 범위를 «구조화된 `specRows` 안»으로 못 박았다.
3. **「더보기」가 펼치기가 «아닐» 수 있다.** 무신사에서 수집기가 `/cs/notice` 로 «떠났다».
   ⇒ 링크는 안 누르고, 눌러서 URL 이 바뀌면 «그 수집을 무효로 선언»한다(`stayed-on-page`).
4. **화장품 축을 의류에 대면 «언제나» 미통과.** 그건 페이지 결함이 아니라 «내 자가 틀린 것».
   ⇒ 카테고리를 «먼저» 고르고 그 축으로만 묻는다.

## 🧭 판정이 «넷»인 이유

```
ok            얻었다
missing       판매자가 안 채웠다          → 사람이 확인 / 판매자에게 요구
unmeasurable  ***이 사다리로는 못 잰다***    → 사람 칸으로 «설계»한다
image-only    🖼️ 자료는 «있는데» 이미지 안  → «OCR 축»을 붙이면 기계가 얻는다
```
⛔ **넷을 같은 값으로 접지 마라 — 처방이 전부 다르다.**
「더 밟으면 채워지나?」가 `missing`/`unmeasurable` 을 가르고(🅕 근거 계급 다섯째 칸 · `#16815`),
「자료가 «어디»에 있나」가 `image-only` 를 가른다.

### 🖼️ 넷째 상태는 무신사에서 «발견»됐다 (2026-09-10)

소재·충전재 스펙이 DOM 에 «한 글자도 없고» 상세 이미지 «안»에 있었다:
```
FABRIC  겉감 나일론 100% · 안감 나일론 100%
        충전재 덕 다운(솜털 80%, 깃털 20%)
FIT     레귤러
```
⛔ 이것을 `missing` 으로 적으면 「판매자가 안 채웠다」가 «거짓»이 되고,
`unmeasurable` 로 적으면 「영영 못 얻는다」가 «거짓»이 된다.
📌 ⇒ ***이름이 «따로» 필요했다*** — 안 그러면 다음 창이 «크롤러를 고치려» 든다.
검사는 「그 축의 텍스트가 없는데 «세로 1500px 이상 상세 이미지»가 있나」로 «잰다».
